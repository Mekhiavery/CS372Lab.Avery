2. RESULTING AI REVIEW

Strengths:
- The Tree uses shared_ptr for child nodes, so memory is managed
  automatically instead of with new and delete.
- Parent links use weak_ptr, which prevents parent-child ownership
  cycles from keeping nodes in memory.
- insert() returns a new Tree instead of modifying the original.
- The class supports searching, copying, moving, and tree traversals.

Weaknesses and possible problems:
- Tree building copies whole subtrees to keep parent links correct.
  This works, but it can be slow when the Tree becomes large.
- The Tree is not balanced, so inserting values in an unlucky order
  can make it tall and slow down searches and inserts.
- The root() function originally used assert() to check for an empty
  tree. In a build with assertions turned off, calling root() on an
  empty tree could cause a crash.
- The parent-pointer test checked certain nodes, but did not check
  that every node had the correct parent link.
- A very deep Tree could cause problems with recursive operations.

Suggestions:
- Make root() throw an exception when the Tree is empty.
- Add a function that checks every parent pointer and extend the tests.
- Keep the current Tree design for this assignment, but note that
  full subtree copying and lack of balancing limit performance.
- Run both the new tests and the professor's original unit tests.

3. CHANGES MADE BASED ON THE REVIEW
